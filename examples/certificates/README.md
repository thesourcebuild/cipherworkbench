# Certificates & mTLS Real-World OpenSSL Verification Examples

This directory provides automated examples, standalone verification scripts, and ready-to-run Python/PowerShell suites that test cryptographic certificates generated by **CipherWorkbench** (`cert-creator` and `mtls-suite`) against native **OpenSSL CLI**, Python SSL sockets, and modern browsers.

---

## 📂 Architecture: Dedicated Folders for Each Deployment Model

Each PKI architecture model has its own self-contained folder containing:
1. `run.ts`: End-to-end automated generation & live OpenSSL test harness.
2. `server.py`: Python HTTPS / mTLS server with certificate validation.
3. `client.py`: Python HTTPS / mTLS client with mutual auth and rejection tests.
4. `commands.ps1`: Turnkey Windows PowerShell management script (`run`, `verify`, `server`, `client`, `trust`).
5. `README.md`: Architecture guide, exact OpenSSL CLI recipes, and trust store instructions.

| Architecture Folder | Hierarchy | Target Environments |
| :--- | :--- | :--- |
| [📁 `single-self-signed/`](file:///i:/projects/cipherworkbench/cipherworkbench/examples/certificates/single-self-signed/README.md) | Single Certificate (Self-Signed) | Local Dev, Dev Containers, Unit / Integration Tests |
| [📁 `single-ca-signed/`](file:///i:/projects/cipherworkbench/cipherworkbench/examples/certificates/single-ca-signed/README.md) | 2-Tier: Root CA ➔ Server Leaf | Team Staging, Internal Web Services, Corporate Intranet |
| [📁 `mtls-2-tier/`](file:///i:/projects/cipherworkbench/cipherworkbench/examples/certificates/mtls-2-tier/README.md) | 2-Tier: Root CA ➔ Server & Client | Microservice Mesh, Zero-Trust API, IoT Device Ingestion |

## 🔒 TLS 1.1, TLS 1.2, and TLS 1.3 Protocol Version Support

All four PKI deployment architectures generated by CipherWorkbench cryptographically support **TLS 1.1**, **TLS 1.2**, and **TLS 1.3**:

| TLS Version | Status | Negotiated Cipher Suite (ECDSA P-256) | Security & Handshake Context |
| :--- | :--- | :--- | :--- |
| **TLS 1.3** | **Supported** (Modern Default) | `TLS_AES_256_GCM_SHA384` | Mandates `digitalSignature` in `keyUsage` (fully compliant). Removes static RSA key exchange. Handshake messages encrypted. |
| **TLS 1.2** | **Supported** (Enterprise Standard) | `ECDHE-ECDSA-AES256-GCM-SHA384` | Supported universally across all operating systems, microservice proxies, and Python `ssl`. |
| **TLS 1.1** | **Supported** (Legacy Compatibility) | `ECDHE-ECDSA-AES256-SHA` | Cryptographically valid. OpenSSL 3.0+ and modern OS require `@SECLEVEL=0` because [RFC 8996](https://datatracker.ietf.org/doc/html/rfc8996) formally deprecated TLS 1.1 in 2021. |

### Testing Protocol Versions with Python (Zero `pip` Dependencies)
Every folder includes Python `server.py` and `client.py` using Python's standard library:
```bash
# Force TLS 1.3
python client.py --tls-version 1.3

# Force TLS 1.2
python client.py --tls-version 1.2

# Force legacy TLS 1.1 (auto-enables @SECLEVEL=0 for OpenSSL 3 compatibility)
python client.py --tls-version 1.1

# Run protocol matrix test across all versions
python client.py --tls-version all
```

### Testing Protocol Versions with Native OpenSSL CLI
```bash
# TLS 1.3 Client
openssl s_client -connect 127.0.0.1:8443 -CAfile ca.crt -tls1_3

# TLS 1.2 Client
openssl s_client -connect 127.0.0.1:8443 -CAfile ca.crt -tls1_2

# TLS 1.1 Client (requires SECLEVEL=0 on OpenSSL 3.0+)
openssl s_client -connect 127.0.0.1:8443 -CAfile ca.crt -tls1_1 -cipher "DEFAULT:@SECLEVEL=0"
```

## 🖥 Manual Interactive Testing with OpenSSL

If you export the suite using the **Export** button in CipherWorkbench, you can also run live interactive tests directly in your terminal:

**Terminal 1 (Mock mTLS Server):**
```bash
openssl s_server -key server.key -cert server.crt -CAfile ca.crt -Verify 1 -port 8443
```

**Terminal 2 (Mock mTLS Client):**
```bash
openssl s_client -connect localhost:8443 -cert client.crt -key client.key -CAfile ca.crt
```
*(Once connected, anything typed in Terminal 2 will be sent across the mTLS encrypted tunnel to Terminal 1!)*
